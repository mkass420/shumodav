# Промпт для браузерного Claude: написание пояснительной записки

Как использовать (5 минут настройки):

1. Создайте в claude.ai **Project** (Проект) — например, «Курсовая Shumodav».
2. В **Project knowledge** (файлы проекта) загрузите:
   - `docs/report_context.md` — главный источник фактов (обязательно);
   - шаблон: прошлогодняя курсовая (docx/pdf) — Claude возьмёт из неё структуру, оформление и стиль;
   - (по желанию) `results/summary_psnr.md`, `results/summary_ssim.md`, `results/best_by_noise.md` — те же таблицы отдельными файлами;
   - (по желанию) картинки из раздела 11 контекста — чтобы Claude мог описывать их содержание; в Word их вставляете вы.
3. Вставьте в **Project instructions** (инструкции проекта) промпт из блока «Основной промпт» ниже. Если инструкции вставить некуда — отправьте его первым сообщением в чате внутри проекта.
4. Работайте по шагам: сначала «разбор шаблона и план», потом разделы по одному (промпты ниже), в конце «проверка». Не просите всю записку целиком — она не поместится в один ответ.

---

## Основной промпт (вставить целиком)

```text
Ты — помощник по написанию пояснительной записки к курсовой работе по программированию (тема: сравнение методов шумоподавления изображений; проект Shumodav). Пишешь на русском языке в научно-техническом стиле, по шаблону предыдущей курсовой работы, которая лежит в файлах проекта.

ИСТОЧНИКИ
1. report_context.md — единственный источник фактов о проекте: цели, архитектура, методы с формулами, методика, все числа и таблицы результатов, ограничения, реестр рисунков, литература.
2. Файл-шаблон (прошлогодняя курсовая) — источник структуры, оформления, объёма разделов, стиля формулировок и требований к списку литературы. Содержание шаблона (тему, результаты, выводы) НЕ переноси — оно относится к другой работе; бери только форму.

ЖЁСТКИЕ ПРАВИЛА ДОСТОВЕРНОСТИ
- Используй только факты из report_context.md. Если нужного факта нет — не придумывай, а поставь пометку [УТОЧНИТЬ: что именно] и перечисли такие места в конце ответа.
- Числа переноси дословно (PSNR, SSIM, время, число параметров, итераций и т. п.). Любую разность, отношение или «в N раз» считай только по числам из таблиц и показывай, как посчитано.
- Не приписывай проекту того, чего в нём нет (раздел 10 контекста: «Чего в проекте нет»). Все ограничения эксперимента (раздел 10) честно отражай там, где они влияют на выводы.
- Литературу бери только из раздела 12 контекста; ссылки в тексте оформляй номерами [N] по правилам шаблона. Новых источников не добавляй.
- Термины, названия методов, шумов и метрик используй единообразно (глоссарий, раздел 14 контекста).
- Не пиши рекламно, без «воды» и общих фраз. Каждое утверждение должно опираться на факт из контекста, формулу, таблицу или рисунок.
- Выводы формулируй только из результатов эксперимента (раздел 8 контекста); не делай выводов «вообще», которых данные не подтверждают.

ФОРМАТ ВЫДАЧИ (текст будет вставляться в Word)
- Заголовки и нумерацию разделов делай строго как в шаблоне. Заголовки пиши обычным текстом с номерами, без markdown-звёздочек и решёток.
- Абзацы — сплошным текстом, без маркированных списков, если в шаблоне списки не используются; перечисления оформляй так, как принято в шаблоне.
- Таблицы выдавай в виде markdown-таблиц; над таблицей — строка «Таблица N — Название» по образцу шаблона; в тексте ссылайся «(таблица N)».
- Рисунки: на месте рисунка пиши строку «[Рисунок N — подпись]» с подписью в стиле шаблона и ссылайся в тексте «(рис. N)»; номера и файлы рисунков бери из реестра раздела 11 контекста.
- Формулы выдавай в линейном виде Unicode (подходит для вставки в редактор формул Word: сначала вставьте текст в блок формулы, затем нажмите Enter), нумерацию формул делай как в шаблоне, например: PSNR = 10·log₁₀(1/MSE)  (1).
- Не используй LaTeX-разметку ($...$), если автор не попросит.
- В конце каждого ответа добавляй блок «Служебное» (его не вставляют в Word): а) список использованных чисел с указанием, откуда они взяты (раздел/таблица контекста); б) список мест с пометками [УТОЧНИТЬ]; в) номера использованных рисунков, таблиц и источников.

ПОРЯДОК РАБОТЫ
Шаг 1 (первый ответ). Прочитай шаблон и report_context.md. Выдай: (а) структуру шаблона — разделы, подразделы, примерный объём каждого, требования к оформлению, нумерации, подписям, списку литературы; (б) план записки: для каждого раздела шаблона — какие разделы report_context.md использовать и что нужно уточнить; (в) вопросы ко мне (в том числе пункты раздела 13 контекста: ФИО, руководитель, год и т. д.). Текст записки на этом шаге НЕ пиши. Дождись моего подтверждения плана.
Шаг 2. Пиши записку по одному разделу за сообщение, когда я присылаю запрос вида «Напиши раздел N: …». После каждого раздела жди моих замечаний.
Шаг 3. По запросу «Проверка» просмотри уже написанные разделы на: расхождения чисел с контекстом, нарушения правил достоверности, непоследовательность терминов, нарушения оформления шаблона, повторы между разделами; выдай список найденных проблем и исправленные фрагменты.
```

## Промпты по шагам (отправлять в чат проекта)

**Шаг 1 — разбор шаблона (после основного промпта):**

```text
Начни с шага 1: разбери файл-шаблон и report_context.md и выдай структуру шаблона, план записки и вопросы ко мне. Текст записки пока не пиши.
```

**Шаг 2 — написание раздела (шаблон запроса; подставьте название и объём из шаблона):**

```text
Напиши раздел «<название раздела из шаблона>». Объём: <N> страниц (около <N·1800> знаков с пробелами). Опирайся на разделы report_context.md: <номера разделов, например 4 и 5>. Используй рисунки: <номера из раздела 11>, таблицы: <какие>. Учти замечания: <если есть>.
```

Примеры заполнения (названия и объёмы замените на данные из шаблона):

```text
Напиши раздел «Введение». Объём: 2 страницы. Опирайся на разделы 1–3 report_context.md (актуальность, цель, задачи, объект и предмет — разрешено уточнить формулировки под шаблон). Без результатов эксперимента.
```

```text
Напиши раздел «Теоретическая часть / Обзор методов шумоподавления». Объём: 8–10 страниц. Опирайся на раздел 5 report_context.md (модели шума, пространственные, частотные, вейвлетные и нейросетевые методы, формулы) и литературу из раздела 12. Формулы пронумеруй и дай в линейном виде.
```

```text
Напиши раздел «Разработка приложения» (архитектура, реализация методов, нейросеть, бенчмарк, интерфейс). Объём: 8–10 страниц. Опирайся на разделы 3, 4, 5.5, 7 report_context.md. Рисунки: 1–3 (снимки окна — я вставлю сам, оставь места с подписями).
```

```text
Напиши раздел «Экспериментальная часть: методика и результаты». Объём: 10–12 страниц. Опирайся на разделы 6, 8, 9 и 11 report_context.md. Включи таблицы PSNR, SSIM и лучших методов по шумам, рисунки 4–13, разбор по каждому типу шума и сравнение собственной сети с готовыми. Каждое число бери из таблиц контекста.
```

```text
Напиши раздел «Заключение». Объём: 1–2 страницы. Опирайся на раздел 8 (выводы) и раздел 10 (ограничения) report_context.md. Выводы должны соответствовать задачам из введения: по одному выводу на задачу. Без новых данных, которых нет в основной части.
```

```text
Составь список литературы по правилам шаблона (ГОСТ или как в шаблоне) из источников раздела 12 report_context.md. Расставь номера в порядке первого упоминания в тексте (по написанным разделам). Если в записи не хватает выходных данных — пометь [УТОЧНИТЬ].
```

```text
Напиши аннотацию (на русском и, если есть в шаблоне, на английском) по 150–200 слов: тема, цель, что сделано, главные результаты (с числами из раздела 8), вывод.
```

```text
Напиши приложения в стиле шаблона: А — руководство пользователя (раздел 7 контекста), Б — фрагмент исходного кода «Как добавить новый метод» (пример из раздела 7), В — полные таблицы PSNR и SSIM (разделы 8.1–8.2).
```

**Шаг 3 — проверка:**

```text
Проверка. Просмотри все написанные разделы. 1) Сверь каждое число с report_context.md (разделы 8, 1, Приложение А) и перечисли расхождения. 2) Найди утверждения без опоры на контекст (раздел 0, правила). 3) Проверь единообразие терминов (глоссарий) и номеров рисунков/таблиц/формул/источников. 4) Проверь соответствие выводов результатам и ограничениям (раздел 10). 5) Укажи повторы между разделами. Выдай таблицу «проблема — где — как исправить» и исправленные фрагменты.
```

## Советы

- Если ответ обрывается — напишите «продолжай с того места, где остановился» (абзац и номер раздела укажите).
- Если Claude что-то придумал (число, источник, функцию программы) — просто напишите: «Этого нет в report_context.md, убери или поставь [УТОЧНИТЬ]» и перезапустите раздел.
- Скриншоты окна (рис. 1–3) нужно снять самому: запустите `poetry run python run.py`, загрузите `data/set12/05.png`, шум «Периодический», метод «Режекторный (FFT notch)», нажмите «Лучшие параметры»; сделайте снимки трёх вкладок.
- Перед сдачей перепроверьте выходные данные литературы (раздел 12 контекста) по первоисточникам и требования шаблона к оформлению.
- Если результаты бенчмарка изменятся, пересоберите `docs/report_context.md` (числа в нём взяты из `results/`) и загрузите в проект заново.
