# План: расчёты GUI в отдельном процессе с отменой

## Context
После Блока 5 расчёты шли в `QThread` внутри процесса GUI. Это давало три проблемы, найденные на практике:
1. Тяжёлый метод (BM3D/NLM/DRUNet) на большой картинке нельзя отменить; новые запросы ждут его конца.
2. Закрытие окна приходилось делать без ожидания и завершать процесс через `os._exit`.
3. Память растёт из-за арен malloc в потоках (лечилось `mallopt` + `malloc_trim`), а пик памяти тяжёлого метода «сидит» в процессе GUI.

## Решение
- `gui/compute.py` (без Qt): дочерний процесс (`spawn`) обслуживает очередь запросов `process` и `compare`; родитель (`ComputeClient`) отправляет их через `multiprocessing.Queue`, опрашивает ответы таймером GUI, умеет **убить** дочерний процесс (отмена) и лениво перезапустить.
- Картинка пересылается в дочерний процесс один раз (кэш по `image_key`), дальше — только параметры.
- Мягкое вытеснение: если во время расчёта пришёл новый запрос, а текущий идёт дольше 2 с — он убивается; короче — ждём (чтобы не перезапускать процесс и не терять загруженные модели при перетаскивании ползунков).
- Кнопка «Отмена» (убивает процесс сразу), обнаружение аварийного завершения дочернего процесса (в т. ч. OOM-killer) без падения GUI, прогрев процесса при старте приложения.
- Убрать `QThread`-воркеры, `limit_malloc_arenas`, `trim_memory`, `os._exit`.

## Проверка
- Тесты GUI (offscreen) переписаны под новую схему: результат, устаревшие запросы, сравнение, отмена тяжёлого метода (BM3D на крупной картинке убивается < 2 с), вытеснение, восстановление после смерти дочернего процесса, закрытие окна.
- Замер памяти GUI-процесса на большой картинке до/после.
