## 1. Архитектура приложения

Приложение — Python-пакет `shumodav` (`src/shumodav/`) из пяти слоёв:

| Слой | Назначение |
|---|---|
| `core` | типы, реестры шумов и методов, модели шума, метрики, pipeline, ввод-вывод изображений |
| `denoisers` | реализации методов: пространственные, частотные, вейвлетные, нейросетевые |
| `nn` | модель DnCNN-Lite, генератор обучающих патчей, скрипт обучения; вендоринг сетей KAIR (DnCNN, DRUNet) |
| `bench` | бенчмарк: `tune` (подбор параметров), `run` (прогон), `report` (таблицы и графики) |
| `gui` | интерфейс на PyQt5 |

Ключевая идея — **единые контракты**, на которых построены остальные слои:

- изображение — массив `float32` в диапазоне [0, 1], форма `H×W` (серое) или `H×W×3` (RGB); методы не меняют вход и возвращают новый массив той же формы;
- метод — класс-наследник `Denoiser` с полями `name`, `label`, `family`, `params` и функцией `denoise(img, **p)`; параметры описываются объектами `ParamSpec` (тип, значение по умолчанию, диапазон, шаг, логарифмическая шкала, сетка значений для подбора, условие видимости);
- шум — класс-наследник `NoiseModel` с функцией `apply(img, rng, **p)` и тремя уровнями (low / mid / high); результат детерминирован при одинаковом seed;
- регистрация через декораторы `@register_noise`, `@register_denoiser`.

Благодаря этому GUI не знает о конкретных методах: панель параметров строится автоматически по `ParamSpec`, а бенчмарк обходит реестр. Добавление нового метода сводится к одному классу (пример — в `README.md`). Необязательные зависимости (`torch`, `bm3d`) подключаются лениво: если их нет, метод сообщает `is_available() == False` и пропадает из списков, остальное приложение работает.

**Pipeline** (`core/pipeline.py`): `apply_noise` (шум с заданным seed), `run_denoiser` (запуск метода с замером времени; для методов без поддержки цвета каналы обрабатываются по отдельности; перед замером нейросети делается один прогревочный прогон), `evaluate` (PSNR/SSIM шумной картинки и результата).

**GUI.** Расчёт идёт в фоновом потоке `QThread`; изменения настроек собираются с задержкой 200 мс (debounce); у каждого запроса есть номер, результаты устаревших запросов отбрасываются; одновременно работает один поток. Ошибки метода выводятся в статус-строку и не роняют приложение. Вкладки: «Изображения» (оригинал / шумное / результат с синхронным масштабированием), «Визуализация» (спектры и визуализация метода), «Сравнение» (прогон всех методов с таблицей PSNR/SSIM/время). Кнопка «Лучшие параметры» подставляет параметры, найденные бенчмарком для ближайшего уровня шума.

## 2. Методы

### 2.1. Модели шума

Пусть `x` — чистое изображение в [0, 1], `y` — зашумлённое; после добавления шума значения обрезаются до [0, 1].

| Шум | Модель | low / mid / high |
|---|---|---|
| Гауссов | `y = x + n`, `n ~ N(0, σ²)`, σ задаётся в единицах 0…255 (`σ/255`) | σ = 15 / 25 / 50 |
| Соль и перец | доля `p` пикселей заменяется на 1 (соль) или 0 (перец) в равных долях, пиксель портится сразу во всех каналах | p = 0.05 / 0.10 / 0.20 |
| Спекл | `y = x + x·n`, `n ~ N(0, σ²)` | σ = 0.10 / 0.20 / 0.30 |
| Пуассона | `y = Poisson(x·P) / P` | P = 100 / 30 / 10 |
| Периодический | `y = x + A·sin(2π·f·(u·cosθ + v·sinθ) + φ)`, `(u, v)` — координаты пикселя, `φ` — случайная фаза | A = 0.10 / 0.20 / 0.30; f = 0.1 цикл/пиксель; θ = 45° |

### 2.2. Пространственные методы

Среднее (`cv2.blur`), медианный, гауссов фильтр, билатеральный (веса по расстоянию и по разнице яркости), нелокальных средних (NLM): значение пикселя — среднее по похожим окрестностям, `w(p, q) = exp(−‖P(p) − P(q)‖² / h²)`; BM3D: поиск похожих блоков, объединение в 3D-группы, фильтрация в области преобразования и агрегирование.

### 2.3. Частотные методы

Изображение `f` переводится в спектр `F = FFT2(f)`, спектр умножается на маску `H(D)`, где `D` — нормированное расстояние до центра спектра (от 0 в центре до 1 в углу), затем выполняется обратное преобразование. Перед преобразованием картинка дополняется отражением границ (паддинг), чтобы снизить краевые артефакты.

- идеальный ФНЧ: `H = 1` при `D ≤ D₀`, иначе `0` (резкий срез, эффект «кольцевания»);
- гауссов: `H = exp(−D² / (2·D₀²))`;
- Баттерворта порядка `n`: `H = 1 / (1 + (D / D₀)^{2n})` — гладкий срез, крутизна задаётся порядком.

Для шумоподавления пропускаются **низкие** частоты; в центре спектра `H = 1`, поэтому средняя яркость сохраняется.

**Режекторный фильтр** (`fft_notch`) против периодического шума: синусоида в спектре даёт два симметричных пика. Алгоритм: спектр серой копии умножается на окно Ханна (для детекции), пики — локальные максимумы амплитуды, превышающие локальный фон в `threshold` раз и лежащие вне центральной зоны; маска `M = ∏ (1 − exp(−d²/(2r²)))` по всем найденным пикам (и их симметричным) подавляет их; маска применяется к спектру исходного изображения.

### 2.4. Вейвлетные методы

Изображение раскладывается в аппроксимацию LL и детали (горизонтальные, вертикальные, диагональные) нескольких уровней: DWT (`wavedec2`) или стационарное SWT (`swt2`, без прореживания). Шум в основном лежит в деталях и распределён по всем коэффициентам, а контуры — в малом числе больших коэффициентов, поэтому коэффициенты деталей подвергаются пороговой обработке:

- мягкий порог: `ŵ = sign(w)·max(|w| − T, 0)`;
- жёсткий порог: `ŵ = w` при `|w| > T`, иначе `0`;
- **BayesShrink**: порог для каждой подзоны `T = σ_n² / σ_x`, где `σ_n = median(|w_HH|) / 0.6745` (оценка шума по самой мелкой диагональной подзоне), `σ_x = √max(σ_y² − σ_n², 0)`, `σ_y²` — дисперсия коэффициентов подзоны.

Цветные изображения переводятся в YCrCb; яркость обрабатывается обычным порогом, а для каналов цветности порог увеличивается в `1 + 5·s` раз и коэффициенты ослабляются в `1 − 0.8·s` раз (`s` — параметр `chroma_strength`). Опциональное финальное билатеральное сглаживание убирает остаточные артефакты.

### 2.5. Нейросетевые методы

- **DnCNN** (Zhang et al., 2017): 20 свёрточных слоёв, *residual learning*: сеть предсказывает шум `R(y)`, результат `x̂ = y − R(y)`; используются готовые «слепые» веса для серых и цветных картинок.
- **DRUNet** (Zhang et al., 2021): U-Net с остаточными блоками; на вход подаётся картинка и карта уровня шума `σ/255`; в бенчмарке `σ` оценивается автоматически (`skimage.restoration.estimate_sigma`); картинка дополняется до размеров, кратных 8.
- **Наша CNN (DnCNN-Lite)**: Conv+ReLU → 8×(Conv+BatchNorm+ReLU) → Conv, ядра 3×3, 48 каналов, 167 569 параметров (в готовой DnCNN — 665 921); residual learning `x̂ = y − R(y)`; вход и выход — один канал.

Обучение нашей CNN:

| | |
|---|---|
| Данные | Train400 (400 серых картинок 180×180), случайные патчи 50×50, 8 вариантов поворота/отражения |
| Шум | на лету, случайный тип из {гауссов σ∈[5,55], «соль и перец» 2–25 %, спекл σ∈[0.05,0.35], Пуассона P∈[5,150]}; сеть «слепая» (уровень шума ей не сообщается); периодического шума нет |
| Функция потерь | MSE (минимизация MSE эквивалентна максимизации PSNR) |
| Оптимизатор | Adam, lr = 1e-3, снижение в 10 раз на 9 000 и 12 750 итерациях |
| Батч / итерации | 128 / 15 000 |
| Железо | Google Colab, NVIDIA T4, смешанная точность (AMP); время обучения: [вставить из лога Colab] |
| Валидация | первые 10 картинок BSD68, уровень mid, раз в 1000 итераций; сохраняется модель с лучшим средним PSNR |

Валидационный PSNR на последней итерации (BSD68, mid): гауссов 28.49 дБ, «соль и перец» 38.82, спекл 28.97, Пуассона 27.64; среднее 30.98 дБ (`results/train_log.csv`, кривые — `results/train_curve.png`).

## 3. Методика эксперимента

**Данные.** Три набора, каждый используется для своей цели (так избегаем утечки данных):

| Набор | Размер | Роль |
|---|---|---|
| Train400 | 400 картинок 180×180 | обучение нашей CNN |
| BSD68 | 68 картинок | валидация CNN во время обучения и подбор параметров классических методов (первые 4 картинки) |
| Set12 | 12 картинок | итоговое тестирование; ни в обучении, ни в подборе не участвовал |

Все картинки серые; для бенчмарка берётся центральный кроп 256×256.

**Шумы и уровни.** 5 типов шума × 3 уровня (таблица в п. 2.1). Для каждой тройки (картинка, шум, уровень) шумная картинка генерируется один раз (seed — `crc32` от строки «имя|шум|уровень»), и все методы получают один и тот же вход; запуски воспроизводимы.

**Метрики.** `PSNR = 10·log₁₀(1 / MSE)` для диапазона [0, 1]; `SSIM(x, y) = ((2μ_xμ_y + c₁)(2σ_xy + c₂)) / ((μ_x² + μ_y² + c₁)(σ_x² + σ_y² + c₂))`, усредняется по окнам (реализация `skimage.metrics`, `data_range = 1`); время обработки одной картинки (`time.perf_counter`, для нейросетей после прогревочного запуска).

**Подбор параметров.** Для каждого метода с непустыми сетками (`ParamSpec.grid`) перебирается декартово произведение значений (не более 60 комбинаций, при превышении — случайная выборка с фиксированным seed); критерий — средний PSNR на 4 картинках BSD68 отдельно для каждого шума и уровня. Результат — `results/best_params.json`. У нейросетевых методов сеток нет: они работают с параметрами по умолчанию (у DRUNet — автоматическая оценка σ).

**Прогон.** `run` проходит по всем (картинка, шум, уровень, метод), пишет строки в `results/results.csv` и может быть продолжен после прерывания. Всего в итоговом CSV 12 методов × 12 картинок × 15 сочетаний шум–уровень.

## 4. Результаты

Основные таблицы и графики (вставить в записку):

- тепловые карты — `results/heatmap_psnr.png`, `results/heatmap_ssim.png`; выигрыш относительно шумной — `results/gain_psnr.png`;
- качество против скорости — `results/speed_vs_quality.png`;
- лучшие методы по шумам — `results/best_by_noise.md`;
- наглядные примеры (кроп 96×96, mid) — `results/examples/<шум>_mid.png`;
- кривые обучения — `results/train_curve.png`.

Краткие итоги (подробно с цифрами — `docs/results.md`):

1. Гауссов шум: лучший метод — готовая DRUNet (30.00 дБ в среднем по уровням); лучший классический — BM3D, отставание от лучшей нейросети составляет 0.69–0.82 дБ в зависимости от уровня.
2. «Соль и перец»: наша CNN (38.58 дБ в среднем) намного превосходит лучший классический метод — медианный фильтр (28.10 дБ); готовые DnCNN и DRUNet на этом шуме почти не работают (18.92 и 17.14 дБ).
3. Спекл: наша CNN лучше всех на всех трёх уровнях (29.49 дБ в среднем).
4. Шум Пуассона: BM3D и нейросети отличаются меньше чем на 0.2 дБ на уровнях mid и high; на low лучше DnCNN.
5. Периодический шум: лучший метод — режекторный FFT-фильтр (34.28 дБ в среднем), прирост относительно шумной картинки 15.47–16.86 дБ; нейросети шум не убирают.
6. Скорость: самый медленный метод — BM3D (0.81 с на картинку 256×256), нейросети — от 0.10 с (наша CNN) до 0.60 с (DRUNet); классические методы, кроме BM3D, работают быстрее 0.05 с.

## 5. Выводы

1. Универсального лучшего метода нет: выбор зависит от типа шума. Для гауссова шума лучшими оказались нейросети (DRUNet, DnCNN) и BM3D, для импульсного — своя CNN (из классики — медианный фильтр), для периодического — режекторный фильтр в частотной области.
2. Нейросети, обученные на одном типе шума (DnCNN, DRUNet — только гауссов), плохо переносятся на другие типы; собственная небольшая CNN (в 4 раза меньше DnCNN), обученная на смеси шумов, на негауссовых шумах превзошла готовые сети и на гауссовом шуме уступила им меньше чем на 1.5 дБ (уровень mid).
3. Классические методы остаются конкурентоспособными: BM3D близок к нейросетям на гауссовом шуме и шуме Пуассона, а простые методы (среднее, медианный, гауссов, билатеральный, ФНЧ в частотной области) работают на порядки быстрее нейросетей: 0.0001–0.0018 с против 0.10–0.60 с на картинку 256×256.
4. Частотные методы эффективны, когда у шума выражена структура в спектре (периодический шум); на шумах со спектром, близким к равномерному, фильтр низких частот неизбежно подавляет и полезные высокочастотные детали (см. примеры в `results/examples/`).
5. Реализованное приложение и бенчмарк воспроизводимы и расширяемы: новый метод или шум добавляется одним классом и автоматически попадает в GUI, сравнение и отчёты.

**Ограничения** (см. `docs/results.md`, п. 6): 12 тестовых картинок и одна реализация шума на каждый уровень; подбор параметров на 4 картинках; готовые сети обучены только на гауссовом шуме; абсолютные значения времени зависят от машины.
