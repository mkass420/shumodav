## 2. Постановка задачи (рекомендованная формулировка)

**Актуальность.** Шумоподавление — одна из базовых задач обработки изображений: шум возникает при съёмке (гауссов, пуассоновский), передаче (импульсный), в специальных видах съёмки (спекл, периодические помехи). Для разных типов шума лучшими оказываются разные методы — от простых фильтров до нейронных сетей, поэтому важно иметь инструмент и методику их объективного сравнения.

**Цель работы.** Разработать приложение для сравнения методов шумоподавления изображений (пространственных, частотных, вейвлетных и нейросетевых) и провести их экспериментальное сравнение на пяти типах шума по метрикам качества и времени обработки.

**Задачи.**
1. Изучить методы шумоподавления: фильтрацию в пространственной области, в частотной области (преобразование Фурье), вейвлет-преобразование, методы на основе анализа паттернов (NLM, BM3D), нейросетевые методы.
2. Реализовать генераторы пяти типов шума (гауссов, «соль и перец», спекл, Пуассона, периодический) с тремя уровнями интенсивности и метрики качества (PSNR, SSIM).
3. Реализовать и объединить единым интерфейсом 12 методов шумоподавления; обучить собственную сверточную нейросеть и интегрировать готовые DnCNN и DRUNet.
4. Разработать графическое приложение для интерактивного сравнения методов и консольный бенчмарк с подбором параметров и автоматическим построением отчёта.
5. Провести эксперимент на независимом тестовом наборе, проанализировать результаты и сформулировать рекомендации по выбору метода.

**Объект исследования** — цифровые изображения, искажённые шумом. **Предмет** — методы шумоподавления и их сравнительная эффективность.

## 4. Архитектура приложения


Приложение — Python-пакет `shumodav` (`src/shumodav/`) из пяти слоёв:

| Слой | Назначение |
|---|---|
| `core` | типы, реестры шумов и методов, модели шума, метрики, pipeline, ввод-вывод изображений |
| `denoisers` | реализации методов: пространственные, частотные, вейвлетные, нейросетевые |
| `nn` | модель DnCNN-Lite, генератор обучающих патчей, скрипт обучения; вендоринг сетей KAIR (DnCNN, DRUNet) |
| `bench` | бенчмарк: `tune` (подбор параметров), `run` (прогон), `report` (таблицы и графики) |
| `gui` | интерфейс на PyQt5 |

Ключевая идея — **единые контракты**, на которых построены остальные слои:

- изображение — массив `float32` в диапазоне [0, 1], форма `H×W` (серое) или `H×W×3` (RGB); методы не меняют вход и возвращают новый массив той же формы;
- метод — класс-наследник `Denoiser` с полями `name`, `label`, `family`, `params` и функцией `denoise(img, **p)`; параметры описываются объектами `ParamSpec` (тип, значение по умолчанию, диапазон, шаг, логарифмическая шкала, сетка значений для подбора, условие видимости);
- шум — класс-наследник `NoiseModel` с функцией `apply(img, rng, **p)` и тремя уровнями (low / mid / high); результат детерминирован при одинаковом seed;
- регистрация через декораторы `@register_noise`, `@register_denoiser`.

Благодаря этому GUI не знает о конкретных методах: панель параметров строится автоматически по `ParamSpec`, а бенчмарк обходит реестр. Добавление нового метода сводится к одному классу (пример — в `README.md`). Необязательные зависимости (`torch`, `bm3d`) подключаются лениво: если их нет, метод сообщает `is_available() == False` и пропадает из списков, остальное приложение работает.

**Pipeline** (`core/pipeline.py`): `apply_noise` (шум с заданным seed), `run_denoiser` (запуск метода с замером времени; для методов без поддержки цвета каналы обрабатываются по отдельности; перед замером нейросети делается один прогревочный прогон), `evaluate` (PSNR/SSIM шумной картинки и результата).

**GUI.** Расчёты выполняются в отдельном процессе (`multiprocessing`, режим `spawn`), с которым окно обменивается задачами и результатами через очереди; изменения настроек собираются с задержкой 200 мс (debounce); у каждого запроса есть номер, результаты устаревших запросов отбрасываются; одновременно выполняется одна задача. Такая схема позволяет прервать тяжёлый метод (процесс завершается принудительно, кнопка «Отмена расчёта»), не накапливает память расчётов в окне и переживает аварийное завершение расчёта; картинка пересылается в процесс один раз, дальше передаются только параметры. Ошибки метода выводятся в статус-строку и не роняют приложение. Вкладки: «Изображения» (оригинал / шумное / результат с синхронным масштабированием), «Визуализация» (спектры и визуализация метода), «Сравнение» (прогон всех методов с таблицей PSNR/SSIM/время). Кнопка «Лучшие параметры» подставляет параметры, найденные бенчмарком для ближайшего уровня шума.



## 5. Методы


### 5.1. Модели шума

Пусть `x` — чистое изображение в [0, 1], `y` — зашумлённое; после добавления шума значения обрезаются до [0, 1].

| Шум | Модель | low / mid / high |
|---|---|---|
| Гауссов | `y = x + n`, `n ~ N(0, σ²)`, σ задаётся в единицах 0…255 (`σ/255`) | σ = 15 / 25 / 50 |
| Соль и перец | доля `p` пикселей заменяется на 1 (соль) или 0 (перец) в равных долях, пиксель портится сразу во всех каналах | p = 0.05 / 0.10 / 0.20 |
| Спекл | `y = x + x·n`, `n ~ N(0, σ²)` | σ = 0.10 / 0.20 / 0.30 |
| Пуассона | `y = Poisson(x·P) / P` | P = 100 / 30 / 10 |
| Периодический | `y = x + A·sin(2π·f·(u·cosθ + v·sinθ) + φ)`, `(u, v)` — координаты пикселя, `φ` — случайная фаза | A = 0.10 / 0.20 / 0.30; f = 0.1 цикл/пиксель; θ = 45° |

### 5.2. Пространственные методы

Среднее (`cv2.blur`), медианный, гауссов фильтр, билатеральный (веса по расстоянию и по разнице яркости), нелокальных средних (NLM): значение пикселя — среднее по похожим окрестностям, `w(p, q) = exp(−‖P(p) − P(q)‖² / h²)`; BM3D: поиск похожих блоков, объединение в 3D-группы, фильтрация в области преобразования и агрегирование.

### 5.3. Частотные методы

Изображение `f` переводится в спектр `F = FFT2(f)`, спектр умножается на маску `H(D)`, где `D` — нормированное расстояние до центра спектра (от 0 в центре до 1 в углу), затем выполняется обратное преобразование. Перед преобразованием картинка дополняется отражением границ (паддинг), чтобы снизить краевые артефакты.

- идеальный ФНЧ: `H = 1` при `D ≤ D₀`, иначе `0` (резкий срез, эффект «кольцевания»);
- гауссов: `H = exp(−D² / (2·D₀²))`;
- Баттерворта порядка `n`: `H = 1 / (1 + (D / D₀)^{2n})` — гладкий срез, крутизна задаётся порядком.

Для шумоподавления пропускаются **низкие** частоты; в центре спектра `H = 1`, поэтому средняя яркость сохраняется.

**Режекторный фильтр** (`fft_notch`) против периодического шума: синусоида в спектре даёт два симметричных пика. Алгоритм: спектр серой копии умножается на окно Ханна (для детекции), пики — локальные максимумы амплитуды, превышающие локальный фон в `threshold` раз и лежащие вне центральной зоны; маска `M = ∏ (1 − exp(−d²/(2r²)))` по всем найденным пикам (и их симметричным) подавляет их; маска применяется к спектру исходного изображения.

### 5.4. Вейвлетные методы

Изображение раскладывается в аппроксимацию LL и детали (горизонтальные, вертикальные, диагональные) нескольких уровней: DWT (`wavedec2`) или стационарное SWT (`swt2`, без прореживания). Шум в основном лежит в деталях и распределён по всем коэффициентам, а контуры — в малом числе больших коэффициентов, поэтому коэффициенты деталей подвергаются пороговой обработке:

- мягкий порог: `ŵ = sign(w)·max(|w| − T, 0)`;
- жёсткий порог: `ŵ = w` при `|w| > T`, иначе `0`;
- **BayesShrink**: порог для каждой подзоны `T = σ_n² / σ_x`, где `σ_n = median(|w_HH|) / 0.6745` (оценка шума по самой мелкой диагональной подзоне), `σ_x = √max(σ_y² − σ_n², 0)`, `σ_y²` — дисперсия коэффициентов подзоны.

Цветные изображения переводятся в YCrCb; яркость обрабатывается обычным порогом, а для каналов цветности порог увеличивается в `1 + 5·s` раз и коэффициенты ослабляются в `1 − 0.8·s` раз (`s` — параметр `chroma_strength`). Опциональное финальное билатеральное сглаживание убирает остаточные артефакты.

### 5.5. Нейросетевые методы

- **DnCNN** (Zhang et al., 2017): 20 свёрточных слоёв, *residual learning*: сеть предсказывает шум `R(y)`, результат `x̂ = y − R(y)`; используются готовые «слепые» веса для серых и цветных картинок.
- **DRUNet** (Zhang et al., 2021): U-Net с остаточными блоками; на вход подаётся картинка и карта уровня шума `σ/255`; в бенчмарке `σ` оценивается автоматически (`skimage.restoration.estimate_sigma`); картинка дополняется до размеров, кратных 8.
- **Наша CNN (DnCNN-Lite)**: Conv+ReLU → 8×(Conv+BatchNorm+ReLU) → Conv, ядра 3×3, 48 каналов, 167 569 параметров (в готовой DnCNN — 665 921); residual learning `x̂ = y − R(y)`; вход и выход — один канал.

Обучение нашей CNN:

| | |
|---|---|
| Данные | Train400 (400 серых картинок 180×180), случайные патчи 50×50, 8 вариантов поворота/отражения |
| Шум | на лету, случайный тип из {гауссов σ∈[5,55], «соль и перец» 2–25 %, спекл σ∈[0.05,0.35], Пуассона P∈[5,150]}; сеть «слепая» (уровень шума ей не сообщается); периодического шума нет |
| Функция потерь | MSE (минимизация MSE эквивалентна максимизации PSNR) |
| Оптимизатор | Adam, lr = 1e-3, снижение в 10 раз на 9 000 и 12 750 итерациях |
| Батч / итерации | 128 / 15 000 |
| Железо | Google Colab, NVIDIA T4, смешанная точность (AMP); время обучения: 18.5 мин (вывод ячейки обучения в `results/train_colab.ipynb`) |
| Валидация | первые 10 картинок BSD68, уровень mid, раз в 1000 итераций; сохраняется модель с лучшим средним PSNR |

Валидационный PSNR на последней итерации (BSD68, mid): гауссов 28.49 дБ, «соль и перец» 38.82, спекл 28.97, Пуассона 27.64; среднее 30.98 дБ (`results/train_log.csv`, кривые — `results/train_curve.png`).

## 6. Методика эксперимента


**Данные.** Три набора, каждый используется для своей цели (так избегаем утечки данных):

| Набор | Размер | Роль |
|---|---|---|
| Train400 | 400 картинок 180×180 | обучение нашей CNN |
| BSD68 | 68 картинок | валидация CNN во время обучения и подбор параметров классических методов (первые 4 картинки) |
| Set12 | 12 картинок | итоговое тестирование; ни в обучении, ни в подборе не участвовал |

Все картинки серые; для бенчмарка берётся центральный кроп 256×256.

**Шумы и уровни.** 5 типов шума × 3 уровня (таблица в п. 2.1). Для каждой тройки (картинка, шум, уровень) шумная картинка генерируется один раз (seed — `crc32` от строки «имя|шум|уровень»), и все методы получают один и тот же вход; запуски воспроизводимы.

**Метрики.** `PSNR = 10·log₁₀(1 / MSE)` для диапазона [0, 1]; `SSIM(x, y) = ((2μ_xμ_y + c₁)(2σ_xy + c₂)) / ((μ_x² + μ_y² + c₁)(σ_x² + σ_y² + c₂))`, усредняется по окнам (реализация `skimage.metrics`, `data_range = 1`); время обработки одной картинки (`time.perf_counter`, для нейросетей после прогревочного запуска).

**Подбор параметров.** Для каждого метода с непустыми сетками (`ParamSpec.grid`) перебирается декартово произведение значений (не более 60 комбинаций, при превышении — случайная выборка с фиксированным seed); критерий — средний PSNR на 4 картинках BSD68 отдельно для каждого шума и уровня. Результат — `results/best_params.json`. У нейросетевых методов сеток нет: они работают с параметрами по умолчанию (у DRUNet — автоматическая оценка σ).

**Прогон.** `run` проходит по всем (картинка, шум, уровень, метод), пишет строки в `results/results.csv` и может быть продолжен после прерывания. Всего в итоговом CSV 12 методов × 12 картинок × 15 сочетаний шум–уровень.

## 7. Руководство пользователя (описание интерфейса)

**Запуск:** `poetry run python -m shumodav.gui.app` (или `python run.py`). Перед запуском должны быть установлены зависимости (`poetry install`), для нейросетевых методов — PyTorch (CPU-сборка) и веса (скрипты `scripts/get_data.py`, `scripts/download_weights.py`; веса собственной сети лежат в репозитории).

**Левая панель:**
- кнопки «Загрузить» и «Сохранить результат»; флажок «Работать в оттенках серого»;
- группа «Шум»: выбор типа шума (гауссов, соль и перец, спекл, Пуассона, периодический), параметры шума (слайдеры и поля ввода, строятся автоматически), seed генератора, флажок «Без шума (картинка уже шумная)» — для обработки изображений с реальным шумом (в этом режиме PSNR и SSIM не считаются, т. к. нет эталона);
- группа «Метод»: выпадающий список методов, сгруппированный по семействам (пространственные, частотные, вейвлеты, нейросети); параметры метода строятся автоматически по его описанию; кнопка «Лучшие параметры» подставляет параметры, найденные бенчмарком для ближайшего уровня выбранного шума;
- группа «Метрики»: PSNR и SSIM шумного изображения и результата, время обработки; кнопка «Отмена расчёта».

**Правая часть — три вкладки:**
1. «Изображения»: оригинал, шумное изображение и результат рядом; масштабирование колесом мыши синхронное для всех трёх; кнопка «Сброс» возвращает вид.
2. «Визуализация»: логарифмические спектры Фурье оригинала, шумного изображения и результата, а также визуализация самого метода (маска фильтра в спектре, найденные пики режекторного фильтра, мозаика вейвлет-коэффициентов); для методов без визуализации выводится сообщение.
3. «Сравнение»: кнопка «Прогнать все методы» последовательно запускает все доступные методы с лучшими (или стандартными) параметрами и заполняет таблицу (метод, семейство, PSNR, SSIM, время); таблицу можно сортировать по любому столбцу; двойной щелчок по строке выбирает метод и подставляет параметры.

**Особенности поведения:** обработка запускается автоматически через 200 мс после последнего изменения настроек; расчёт идёт в отдельном процессе, поэтому интерфейс не «замирает», а долгий расчёт можно прервать кнопкой «Отмена расчёта»; ошибки метода отображаются в строке состояния, не закрывая программу.

**Консольный бенчмарк:**
```
python -m shumodav.bench.tune [--quick]     # подбор параметров на BSD68 -> results/best_params.json
python -m shumodav.bench.run  [--quick]     # прогон на Set12 -> results/results.csv
python -m shumodav.bench.report             # таблицы и графики -> results/
```

**Как добавить новый метод:** создать класс-наследник `Denoiser` с полями `name`, `label`, `family`, `params` и функцией `denoise`, пометить декоратором `@register_denoiser`; метод автоматически появится в списке GUI с панелью параметров, в таблице сравнения и в бенчмарке (пример кода — в README репозитория).

| DRUNet (готовая) | neural | 0.5971 | 23.45 |

Средний PSNR нашей CNN самый высокий (28.59 дБ), но он сильно подтянут «солью и перцем». Без этого шума (12 сочетаний) три лучших по среднему PSNR: Наша CNN (26.09), DnCNN (готовая) (25.92), BM3D (25.83).

- Самый медленный метод — BM3D (0.81 с), нейросети работают за 0.10 с (наша CNN), 0.22 с (DnCNN), 0.60 с (DRUNet).
- Методы быстрее 0.05 с: Билатеральный, ФНЧ (FFT), Режекторный (FFT notch), Гауссов фильтр, Среднее, Медианный, Нелокальных средних, Вейвлет (DWT/SWT).

#### Ограничения

- Тест: 12 серых картинок Set12, центральные кропы 256×256; для каждой пары (картинка, уровень) использована одна реализация шума. Доверительные интервалы не считались.
- Параметры классических методов подбирались на 4 картинках BSD68 перебором по небольшой сетке (не более 60 комбинаций). Параметры DnCNN/DRUNet/нашей CNN не подбирались; DRUNet получает оценку уровня шума автоматически (`sigma=auto`), а не истинное значение, поэтому результат может быть чуть ниже максимально возможного.
- Время работы: нейросети замерялись после прогрева; в процессе полного прогона на ноутбуке параллельно выполнялись другие задачи, поэтому абсолютные значения времени ориентировочные (порядок величины и сравнительные соотношения надёжны).
- Готовые DnCNN и DRUNet обучены авторами только на гауссовом шуме. Наша CNN — на смеси четырёх типов шума без периодического, поэтому прямое сравнение на негауссовых шумах отражает не только архитектуру, но и обучающие данные.
- Кривая обучения (`results/train_curve.png`): около 6000-й итерации валидационный PSNR всех шумов кратковременно проваливается, затем восстанавливается и к 15000-й итерации выходит на плато; для итоговых весов использована лучшая по среднему валидационному PSNR модель.

Значения валидационного PSNR на последней (15 000-й) итерации (BSD68, уровень mid): гауссов 28.49 дБ, «соль и перец» 38.82, спекл 28.97, Пуассона 27.64; среднее 30.98 дБ. ## 9. Тестирование

Автоматические тесты (112, pytest) покрывают: модели шума (детерминизм при одном seed, сохранение формы и типа, диапазон [0, 1], статистика гауссова шума и доли «соли и перца»); метрики (PSNR идентичных изображений равен бесконечности, совпадение с формулой, SSIM); ввод-вывод; pipeline и реестры (в том числе поканальная обработка и отбрасывание лишних параметров); «дымовой» тест всех методов на серых и цветных изображениях (форма, тип float32, диапазон [0, 1], неизменность входа); проверки по смыслу (ФНЧ сохраняет среднюю яркость; режекторный фильтр повышает PSNR на периодическом шуме не менее чем на 5 дБ; медианный фильтр улучшает результат на «соли и перце»; готовые DnCNN и DRUNet дают PSNR выше 29 дБ на гауссовом шуме σ=25); обучение сети (быстрый режим обучения, возобновление с контрольной точки); бенчмарк (воспроизводимость seed, подбор по сетке, возобновление прогона, формирование таблиц); GUI в режиме без экрана (создание окна, загрузка изображения, запуск всех методов на трёх типах шума, режим «Без шума», отбрасывание устаревших запросов, таблица сравнения, отмена тяжёлого расчёта, вытеснение долгого расчёта новым запросом, восстановление после аварийного завершения процесса расчёта, закрытие окна во время расчёта); пример добавления нового метода из README. Тест качества нейросетей и быстрый режим обучения пропускаются, если нет данных или весов. Команда запуска: `QT_QPA_PLATFORM=offscreen poetry run pytest -q`.

## 10. Ограничения и чего в проекте НЕТ

**Ограничения эксперимента:**
- тест — 12 серых картинок Set12 (кропы 256×256), одна реализация шума для каждой пары (картинка, уровень), доверительные интервалы не считались;
- параметры классических методов подбирались перебором по небольшой сетке (не более 60 комбинаций) на 4 картинках BSD68; параметры DnCNN, DRUNet и собственной сети не подбирались; DRUNet получает автоматическую оценку уровня шума, а не истинное значение;
- готовые DnCNN и DRUNet обучены авторами только на гауссовом шуме; собственная сеть — на смеси четырёх типов шума без периодического; поэтому на негауссовых шумах сравнивается не только архитектура, но и обучающие данные;
- абсолютные значения времени зависят от компьютера и загрузки (параллельно с прогоном на машине выполнялись другие задачи), надёжны порядки величин и соотношения;
- цветные изображения в бенчмарке не использовались (стандартные наборы серые); в приложении цветные изображения поддерживаются (поканально или в YCrCb);
- собственная сеть — небольшая (167 569 параметров), обучалась 15 000 итераций (18.5 мин).

**Чего в проекте НЕТ** (не упоминать как реализованное): GPU/OpenCL-ускорения в приложении (GPU использовался только в Colab для обучения); смешивания результата с оригиналом, усиления деталей/контраста и «авто-оптимизации» параметров (были в прежней версии v1; в v2 авто-оптимизацию заменил подбор параметров бенчмарком); измерения потребления памяти методами; пакетной обработки файлов; обработки видео; методов на основе трансформеров и диффузии; обучения на реальных (не синтетических) шумах.

## 14. Глоссарий

|---|---|

| SSIM | индекс структурного сходства, от 0 до 1; больше — лучше |

| NLM | метод нелокальных средних (Non-Local Means) |

| DnCNN | сверточная сеть для шумоподавления с остаточным обучением (Zhang et al., 2017) |
| DRUNet | U-Net с остаточными блоками для шумоподавления (Zhang et al., 2021) |
| DnCNN-Lite | собственная облегчённая сеть проекта (10 слоёв, 48 каналов, 167 569 параметров) |
| residual learning | остаточное обучение: сеть предсказывает шум, результат = вход − предсказанный шум |
| Train400 / BSD68 / Set12 | наборы изображений: обучение / валидация и подбор параметров / итоговый тест |
| бенчмарк | программа, прогоняющая все методы на тестовом наборе и формирующая таблицы и графики |
